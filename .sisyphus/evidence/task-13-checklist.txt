## Quarter-Close Release Checklist

This section provides the sign-off procedure for the `nndeploy::egraph` subsystem.

### 1. Adoption Checklist

Confirm the following core workflows are operational by running the mapped test targets:

1.  **Smoke Scenario**: Run `./build/egraph_test --gtest_filter=SmokeTest.EndToEndAdoptionFlow` and confirm PASSED. This verifies the end-to-end integration of expression construction, saturation, extraction, and explanation.
2.  **Edge-Case Resilience**: Run `./build/egraph_test --gtest_filter=EdgeCaseResilienceTest.*` and confirm PASSED. This verifies the system remains stable under redundant merges, cyclic graphs, and no-match rewrite paths.
3.  **Cookbook Workflows**: Run `./build/egraph_test --gtest_filter=CookbookWorkflowTest.*` and confirm PASSED. This ensures all documented code snippets in this README are executable and correct.
4.  **Public API Stability**: Run `./build/egraph_test --gtest_filter=ApiStabilitySmokeTest.*` and confirm PASSED. This verifies that the intended public entry points are accessible and functional.
5.  **Diagnostic Integrity**: Run `./build/egraph_test --gtest_filter=RunnerTest.*` and confirm PASSED. This ensures that the `Runner` correctly reports stop reasons, timing, and rule application statistics.

### 2. Support Expectations

Internal consumers can expect the following support for this quarter:

-   **Defect Response**: Critical regressions in the "Stable" API surface (as defined in the Stability Status section) will be prioritized for immediate fixes.
-   **Guidance**: Support for mapping complex rewrite problems to the current `RecExprBuilder` and `PatternBuilder` ergonomics.
-   **No Silent Breakage**: We commit to the breaking-change policy documented in the Quarter Contract.

### 3. Evidence Required for Broader Adoption

Before declaring the subsystem ready for broader use beyond the current pilot group, the following evidence is required:

-   **Full Suite Pass**: All 176+ tests must pass across all supported build variants (Linux, macOS, Windows).
-   **Regression Immunity**: No regressions in `InteropWorkflowTest.*` or `ErrorContractTest.*`.
-   **Performance Baseline**: Saturation runs on the pilot scale must complete within the `withTimeLimit` defaults without hitting `NodeLimit` unexpectedly.

### 4. Explicit Deferred Items

The following features are not part of the current release and are deferred to future quarters. Refer to the **Next-Quarter Decision Package** for prioritization rules.

-   **S-expression Parser**: Pattern and expression authoring remains manual via C++ builders.
-   **Incremental Rebuild**: Rebuild performance remains global; high-throughput saturation on very large graphs (10k+ nodes) may require incremental optimization.
